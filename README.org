#+title: Personal Emacs Configuration

A modern, literate Emacs configuration using =org-mode= and =straight.el= for package management. This configuration emphasizes Python development, org-mode productivity, and a clean, efficient interface.

* Features

- *Literate Configuration*: Written in org-mode, the configuration self-documents and tangles to =init.el=
- *Modern Package Management*: Uses =straight.el= with =use-package= for reproducible package installation
- *Development Tools*:
  - Python development environment with LSP support via =pylsp=
  - Tree-sitter integration for better syntax handling
  - Git integration with Magit and git-gutter
  - YAML mode for configuration files
- *Enhanced Interface*:
  - Doom themes and modeline for a modern look
  - Ivy/Counsel for completion
  - Which-key for command discovery
  - Helpful for better help buffers
- *Org-mode Configuration*:
  - Custom capture templates for various content types
  - Structured task management with custom TODO states
  - Calendar integration with org-agenda
  - Beautiful typography with mixed-pitch mode
- *MacOS Support*:
  - Custom key bindings for MacOS compatibility
  - High DPI display optimizations
  - MacOS-specific font configuration

* Installation

1. Back up your existing =.emacs.d= if you have one:
   #+begin_src bash
   mv ~/.emacs.d ~/.emacs.d.backup
   #+end_src

2. Clone this repository:
   #+begin_src bash
   git clone https://github.com/rmorison/.dotfiles.git ~/.dotfiles
   #+end_src

3. Create symbolic links:
   #+begin_src bash
   mkdir -p ~/.emacs.d
   ln -s ~/.dotfiles/.emacs.d/Emacs.org ~/.emacs.d/
   ln -s ~/.dotfiles/.emacs.d/init.el ~/.emacs.d/
   ln -s ~/.dotfiles/org ~/org
   mkdir -p ~/.local/bin
   ln -s ~/.dotfiles/bin/claude-acct ~/.local/bin/
   #+end_src

4. Start Emacs - =straight.el= will automatically install all packages. The configuration will automatically tangle =Emacs.org= to =init.el= whenever you save changes to =Emacs.org=.

** MacOS-Specific Setup

1. Install required packages via Homebrew:
   #+begin_src bash
   brew install svn
   brew tap homebrew/cask-fonts
   brew install --cask font-fira-code font-fira-mono
   brew install --cask font-cantarell
   brew install coreutils
   #+end_src

2. Configure keyboard modifiers in System Settings:
   - Caps Lock Key → Control
   - Control Key → Option
   - Option Key → Command
   - Command Key → Command

The configuration includes MacOS-specific overrides that:
- Adjust font sizes for Retina/high DPI displays
- Map modifier keys for a more ergonomic experience
- Use GNU ls (gls) for dired mode compatibility

* Scripts

** claude-acct

Runs Claude Code under a named account:

#+begin_src bash
claude-acct <account> [claude args...]
#+end_src

Claude Code takes its identity from ambient state — a Keychain login, or an
OAuth token in the environment — which is awkward to control from an editor,
since editors exec the binary directly and never source a shell. This script
makes the account an explicit argument.

Accounts are configured by environment, so the script holds no site-specific
values. For an account (upper-cased, ~-~ as ~_~) the token comes from the first
of these that is set, and a session with neither runs under whatever
~claude /login~ last established:

| Variable                          | Meaning                                                |
|-----------------------------------+--------------------------------------------------------|
| ~CLAUDE_ACCT_TOKEN_<ACCOUNT>~     | The OAuth token itself. Checked first.                 |
| ~CLAUDE_ACCT_TOKEN_REF_<ACCOUNT>~ | A 1Password reference to read it from                  |
| ~CLAUDE_ACCT_AMBIENT_<ACCOUNT>~   | Declare that this account uses the ambient login       |
| ~CLAUDE_ACCT_CLAUDE_BIN~          | Path to the real =claude= binary                       |

#+begin_src bash
export CLAUDE_ACCT_TOKEN_WORK="sk-ant-oat..."           # no secret manager
export CLAUDE_ACCT_TOKEN_REF_WORK="op://Vault/id/cred"  # or via 1Password
claude-acct work   # token-authenticated
claude-acct me     # ambient login
#+end_src

~op~ is optional — it is consulted only for accounts configured with a ~_REF~
and no direct token, so setups without 1Password work unchanged. The trade-off
is that a direct token stays in the environment and is inherited by child
processes, whereas the ~_REF~ form keeps it out of the environment and makes
each session start a prompted, explicit authorization.

~ANTHROPIC_API_KEY~ and ~ANTHROPIC_AUTH_TOKEN~ are cleared for *every* account.
Either outranks both an OAuth token and the Keychain login in Claude Code's
auth precedence, so a stray key silently changes how the session is billed —
and Emacs inherits the login shell's environment wholesale, so a key set once
reaches every session it spawns.

An account with no token runs under the ambient login and says so on stderr,
since that is also what a typo'd account name looks like; declaring
~CLAUDE_ACCT_AMBIENT_<ACCOUNT>~ states the intent and silences the notice.

Emacs picks the account per directory and invokes this script; see the Account
Selection section of =Emacs.org=. The script must be on ~PATH~ — the install
step above links it into =~/.local/bin=.

* Dependencies

- Emacs 29+ (for native tree-sitter support)
- Python 3.12+ (for Python development features)
- Git
- [[https://github.com/tonsky/FiraCode][Fira Code]] and [[https://fonts.google.com/specimen/Cantarell][Cantarell]] fonts
- Node.js (for Mermaid diagrams)

** Optional Dependencies

- [[https://developer.1password.com/docs/cli/][1Password CLI]] (~op~) — only for ~bin/claude-acct~ accounts configured with
  ~CLAUDE_ACCT_TOKEN_REF_*~; accounts using a direct token or the ambient login
  do not need it
- pyenv or similar for Python virtual environment management
- [[https://www.nerdfonts.com/][nerd-fonts]] for icons

* Customization

The configuration is primarily controlled through =Emacs.org=. This file is organized into logical sections with detailed comments explaining each configuration choice. When you save changes to =~/.dotfiles/.emacs.d/Emacs.org=, it will automatically tangle to =init.el=. You'll need to restart Emacs or evaluate the changed sections to apply the updates.
